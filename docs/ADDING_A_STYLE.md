# Adding a martial art

Styles are data. The match code never checks a style's name.

1. **Moves.** Reuse rows from `CombatData.ATTACK_TABLE` where you can. For a new move:
   1. Append a value to `AttackType`. Never reorder this enum.
   2. Add a table row with a permanent `id` and its frame data, hitbox, damage, posture and cancel window. Set `air: true` for jump-only moves and `spin: true` for moves that turn the back. A leaping move (for example a power move) sets `leap` (vertical speed), `leap_at` (takeoff tick) and `leap_vx` (forward speed). Its hitbox is relative to the feet at the height reached on the first active tick, so measure where the striking limb is drawn at contact and centre the hitbox there. Landing ends the move, and the landing recovery runs out the rest of startup + active + recovery. `no_strike: true` marks a technique with no hitbox (a weave or a feint) that chains without contact.
   3. Add keyframe poses and a timeline in `FighterVisual._moves`, plus the striking joint in `_attack_joint`.
2. **Stance.** Reuse a `Stances.Kind`, or append a new one with its guard pose and active idle. Never reorder this enum either.
3. **Style file.** Copy `styles/boxing.tres` to `styles/<id>.tres` and set:
   - `id`: permanent; saves refer to it.
   - `order`, `display_name`, `description`, `category`, `difficulty`, `strengths`, `weaknesses`, `stance`.
   - `input_map` and `air_map`: slot → move id. The slots are listed in `MartialArtStyle`: J `light`, K `heavy`, L `technique`, `up_light` / `up_heavy` (W), `down_light` / `down_heavy` (S), the Space chords `power_light` / `power_heavy`, and X `x_move` (ground only, never in `air_map`). X attacks set `x_move: true` and their own `x_cooldown_frames`; keep normal defense and committed recovery.
   - `quotes` (optional): speech-bubble lines by event (`match_start`, `slap`, `hurt`, `block`, `miss_heavy`, `low_health`, `victory`).
   - `move_names` (optional): the style's own name for a shared move, for example karate's `jab` is its "Straight Punch".
   - `chains`: move id → the move ids it may cancel into on contact.
   - `ai_close_plans`, `ai_far_plans`, `ai_preferred_range`.
   - `step_scale` (optional, default 1): how far the style's strikes step in.
     Short-range styles need more footwork to get inside long-range ones.
   - `ai_tuning` (optional): rival AI overrides for the style, from
     `EnemyAI.TUNABLE`, for example `{"aggression": 0.8, "parry_chance": 0.3}`.
   - `kit` (optional): the character outfit, one of `&"boxing"`, `&"muay_thai"`, `&"karate"`, `&"kung_fu"`, `&"taekwondo"`, `&"kickboxing"`, `&"bangla_maar"`, or the plain `&"gi"` silhouette (default). A new outfit is a colour table in `FighterVisual._build_outfit` (which body parts are cloth) plus its details in the `_leg_extras` / `_arm_extras` / `_torso_extras` / `_head_extras` hooks.
   - Balance the new style by running AI-vs-AI matches against every style
     (both sides AI, several seeds). The current styles sit between about
     45% and 60%.
4. **Validate.** Run `tests/run_all.sh`. `StyleRegistry` refuses a malformed file and names every problem in `StyleRegistry.rejected()`, for example:
   - an unknown move,
   - a chain that leaves the moveset,
   - an AI plan that isn't a legal chain,
   - an air-only move mapped to a ground slot.

The new style then appears in the selection roster. The selector currently fits nine styles in a three-column grid; its details scroll while all cards and the confirm button stay visible. Test the layout before expanding beyond nine. Both the player and the AI rival can use it, and the `Fighter` gate keeps every fighter inside its own moveset.

**Not covered by data alone.** Throws, grips, clinches and ground positions (Judo, Wrestling, BJJ, Sambo, Hapkido locks) need a synchronized two-fighter interaction subsystem. See `docs/M6.5_ARCHITECTURE.md` §4.

## Integration checks

Update the independent published mappings in `tests/test_controls.gd`, explicit roster counts in `test_styles.gd` and `test_bangla.gd`, and finisher IDs in `test_finisher_contact.gd`. Registry-driven signature, X, training and census checks automatically include a new resource. Keep both facing directions and wall contact coverage.

The AI reads plans and ranges from the resource. Anti-air first uses its established legal moves, then the style's rising/high slots if none match; verify the chosen strike can reach an airborne opponent. Add dedicated music to `GameAudio.MUSIC_FILES` only when an actual track exists. Capoeira and Jeet Kune Do have separate synthesized OGG arrangements generated by `tools/music/gen_expansion_music.py`; unknown future styles retain the procedural fallback.
